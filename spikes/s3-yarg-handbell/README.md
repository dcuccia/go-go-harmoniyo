# S3 Phase B — YARG handbell harness

Spike code for [S3](../../docs/spikes/README.md#s3--yarg-handbell-mode). Report: the
[Phase B section of the S3 report](../../docs/spikes/S3-report.md#phase-b-results).

A headless .NET 10 console app that runs **YARG.Core** (the engine YARG uses) together with the Unity-free
HGP code from the fork branch [`dcuccia/YARG@handbell-spike`](https://github.com/dcuccia/YARG/tree/handbell-spike)
(`Assets/Script/Integration/Hgp/Core`). It answers the parts of Phase B that need no Unity Editor:

| Command | What it shows |
|---|---|
| `selftest` | Bridge packet parsing, clock mapping, lookbehind queue, and the slot → instrument mapping (all Five-Lane Keys) |
| `prepare <s5Exports> <outSongs>` | Copies the [S5](../s5-chart-pipeline/) song folders and renders one bell stem per ringer (`guitar/bass/rhythm/keys.wav`), so YARG accepts them |
| `scan <songs>` | Runs YARG.Core's own song scanner (`CacheHandler.RunScan`) and `SongEntry.LoadChart()`; lists each ringer part |
| `latency <songs>` | Drives the stock `YargFiveLaneKeysEngine` frame by frame (60 fps), the way `BasePlayer` does. Inputs are source-timestamped and arrive late (network models). Compares stock YARG with the fork's lookbehind at several budgets |
| `send` | UDP sender for the fork's `HgpBridge` (`-hgp`): joins N simulated ringers and can play a song's charts. This is a smoke test until the S1 sidecar exists |

## Reproduce

Requires the .NET SDK 10 and git. The S5 exports are on branch `dcuccia-s5-carol-chart-pipeline`
(PR #3) until it merges.

```powershell
cd spikes/s3-yarg-handbell
./fetch-yarg-fork.ps1                                  # ~10 s, sparse; no LFS, no Unity
dotnet build src/S3Harness -c Release
$h = "src/S3Harness/bin/Release/net10.0/S3Harness.exe"
& $h selftest

# S5 exports -> YARG song folders (from PR #3's branch until it merges)
git -C (git rev-parse --show-toplevel) archive origin/dcuccia-s5-carol-chart-pipeline spikes/s5-chart-pipeline/exports | tar -x -C $env:TEMP
& $h prepare "$env:TEMP/spikes/s5-chart-pipeline/exports" out/songs
& $h scan out/songs
& $h latency out/songs --human 0 --clock 0 --seeds 5
& $h latency out/songs --human 20 --clock 5 --seeds 5 --budgets 0,40,60

# With YARG (fork) running with -hgp, from a second terminal:
& $h send --ringers 4 --song out/songs/silent-night --net typical --countdown 5
```

To build against a full fork checkout instead: `dotnet build src/S3Harness -p:YargForkDir=C:\Projects\YARG-handbell`.

To play the prepared songs in YARG: add `out/songs` as a song folder in YARG's settings, then rescan.
